以下のQ1〜Q12は、この確認テーマを質問形式にしたものです。

### Q1. `open()`はファイルの内容を返しますか？【最優先・ex0】

**回答例：** いいえ、ファイルを操作するためのファイルオブジェクトを返します。このコードの`open(file_name, "r")`はテキストモードなので、通常のファイルでは`_io.TextIOWrapper`です。内容を文字列として取得するのは、その後の`file.read()`です。

補足：`typing.IO[str]`は型ヒント上の表現です。ファイルの内容そのものが`typing.IO[str]`になるわけではありません。バイナリモードの`open()`では別の種類のファイルオブジェクトになります。

### Q2. このコードの読み込み手順を説明してください。【最優先・ex0】

**回答例：** 引数の個数を確認してファイル名を取り出し、`open(..., "r")`で開き、`read()`で内容を取得し、`finally`で閉じます。成功した場合だけ内容を表示し、開く・読む・閉じる処理で対象の例外が起きたら、エラーを表示して終了します。

### Q3. `"r"`と`"w"`は何が違いますか？【最優先・共通】

**回答例：** `"r"`は読み込み用で、存在しないファイルは開けません。`"w"`は書き込み用で、ファイルがなければ作り、すでにあれば開いた時点で既存の内容を空にします。親ディレクトリがなければ`"w"`でも作成できません。

注意：既存の内容が消えるのは`write()`を呼んだ時点ではなく、`open(..., "w")`が成功した時点です。

### Q4. なぜファイルを閉じますか？【最優先・共通】

**回答例：** OSのファイル資源を解放するためです。書き込み時は、バッファに残ったデータを出力する役割もあります。ガベージコレクション任せにせず、使い終わった時点で確実に閉じます。

補足：`close()`だけで、停電時にも必ずデータが保存されることまで保証するわけではありません。

### Q5. ファイルがない場合と権限がない場合、何が起きますか？【最優先・例外処理】

**回答例：** 読み込み対象が存在しない場合は`FileNotFoundError`、アクセス権限がない場合は`PermissionError`が発生します。どちらも`OSError`の子クラスなので、現在の`except OSError`を含む指定で捕捉できます。

### Q6. なぜ`open()`だけでなく`read()`も例外処理の対象にしていますか？【最優先・例外処理】

**回答例：** 開くことに成功しても、その後の読み込みでI/Oエラーや文字コードの変換エラーが起きる可能性があるからです。書き込みやクローズ時にも失敗する可能性があるため、それらも処理対象にしています。

### Q7. `try`・`except`・`finally`の役割を説明してください。【最優先・ex0〜ex2】

**回答例：** `try`には失敗する可能性のある処理を書きます。`except`は指定した例外を処理します。`finally`は、その`try`に入った後、正常終了でも例外発生でも実行される後片付けの処理です。今回のコードではファイルを閉じるために使っています。

補足：通常の例外や`return`では実行されますが、プロセスの強制終了などでも必ず実行されるという意味ではありません。

### Q8. なぜ`try`が入れ子になっていますか？【最優先・ex0〜ex2】

**回答例：** 内側の`try/finally`で、開いたファイルを読み込みの成否にかかわらず閉じます。外側の`try/except`で、開く・読む・閉じる処理の例外を捕捉します。`open()`が失敗した場合は内側の`try`に入らないので、未作成の変数に対して`close()`することもありません。

### Q9. `with open(...) as f:`は何をしますか？【最優先・ex3】

**回答例：** ファイルを開き、ブロック内で利用し、ブロックを抜けるときに自動で閉じます。正常終了だけでなく、途中の例外や`return`でも閉じる処理が行われます。ex0〜ex2で手動で書いた後片付けを簡潔に表現できます。

### Q10. `with`を使えば例外も自動で処理されますか？【最優先・ex3】

**回答例：** 通常のファイルの`with`は、後片付けをしますが、例外を自動で消してはくれません。そのため外側に`try/except`を置き、失敗時は`(False, エラーメッセージ)`を返しています。

深掘りされたら：コンテキストマネージャーは`__enter__()`と`__exit__()`の仕組みを使います。ファイルの終了処理ではクローズが行われます。自作のコンテキストマネージャーには例外を抑制するものもありますが、通常のファイルの`with`と区別して説明します。

### Q11. `with`の中に`return`がありますが、ファイルは閉じますか？【最優先・ex3】

**回答例：** はい。戻り値を評価した後、関数から戻る前に`with`の終了処理が行われます。閉じる処理で`OSError`などが起きた場合は外側の`except`に移り、現在の実装では成功ではなく失敗のタプルを返します。

### Q12. `secure_archive()`の仕様を説明してください。【最優先・ex3】

**回答例：** 必須のファイル名と、省略可能な操作指定と書き込み内容を受け取ります。現在のデフォルト操作は`"read"`、内容は空文字列です。戻り値は`tuple[bool, str]`で、読み込み成功なら`(True, 内容)`、書き込み成功なら`(True, 成功メッセージ)`、失敗なら`(False, エラーメッセージ)`を返します。未対応の操作指定も失敗として返します。

## 課題要件と現在のコードから想定する追加質問

以下はPDFの要件や実装から考えた対策用の質問です。個々の質問がPDFに出題予告として書かれているわけではありません。

### Q13. なぜ`len(sys.argv) != 2`なのですか？【ex0〜ex2】

**回答例：** `sys.argv[0]`にスクリプト名、`sys.argv[1]`にファイル名が入るためです。必要なファイル名は1つですが、リストの要素数は2になります。個数を先に確認することで、引数不足による`IndexError`も防ぎます。

### Q14. 相対パスは何を基準に解決されますか？【共通】

**回答例：** 実行時のカレントディレクトリが基準です。Pythonファイルが置かれている場所ではありません。例えば課題ルートから実行するなら、`python3 ex0/ft_ancient_text.py ex0/ancient_fragment.txt`のように指定します。

### Q15. `read()`の戻り値は？ 2回呼ぶとどうなりますか？【ex0】

**回答例：** 今回はテキストモードなので`str`です。引数なしの`read()`は現在位置から末尾まで読みます。一度末尾まで読んだ後、ファイル位置を戻さずに再度呼ぶと、通常は空文字列が返ります。

補足：ファイル全体を一度に読み込むため、とても大きなファイルではメモリ使用量が増えます。

### Q16. `UnicodeError`とは何ですか？ なぜ`OSError`と両方書いていますか？【共通】

**回答例：** 文字とバイト列の変換に関する例外です。読み込み時には`UnicodeDecodeError`、書き込み時には`UnicodeEncodeError`が起こり得ます。どちらも`UnicodeError`の子クラスですが、`UnicodeError`自体は`OSError`の子クラスではないので、両方を指定しています。

補足：現在のコードでは`encoding`を指定していないため、テキストの文字コードはPythonの実行環境の設定に従います。すべての環境でUTF-8になる、と説明しないようにします。

### Q17. `as e`と`str(e)`は何ですか？【共通】

**回答例：** `as e`は、捕捉した例外オブジェクトを`e`という変数で受け取る指定です。`str(e)`でその例外のメッセージを文字列にできます。f文字列の`{e}`でも、通常は同じ文字列表現が使われます。

### Q18. 行末に`#`を追加する処理を説明してください。【ex1・ex2】

**回答例：** `splitlines()`で改行を除いた行ごとのリストに分け、各行に`"#\n"`を追加して連結しています。例えば`"a\nb\n"`を`"a#\nb#\n"`にします。

追加で聞かれたら：空ファイルは空のままです。途中の空行には`#`が付きます。元の最終行に改行がなくても、変換後には改行が付きます。

### Q19. `write()`と`print()`はどう違いますか？【ex1・ex2】

**回答例：** `write()`は指定された文字列を書き込み、改行を自動では追加しません。テキストファイルへの`write()`は書き込んだ文字数を返します。`print()`はデフォルトで標準出力に表示し、末尾に改行を追加します。

### Q20. なぜ保存成功のメッセージは`close()`の後なのですか？【ex1・ex2】

**回答例：** `write()`が終わっても、バッファのデータを出力するクローズ時に失敗する可能性があるためです。閉じるところまで成功した後に、保存できたと表示します。

注意：現在のコードは、途中まで書き込んだ内容を元に戻す機能までは持っていません。書き込み失敗時に元のファイルを必ず保護できる、とは説明しません。

### Q21. 空入力とEOFは何が違いますか？【ex1・ex2】

**回答例：** 空入力はEnterだけを押した状態で、入力ストリーム自体は終了していません。EOFは入力が終了した状態です。`input()`は空入力なら`""`を返し、入力を何も読めずEOFになった場合は`EOFError`を出します。

補足：Macのターミナルでは、通常、空の入力行でControl + Dを押すとEOFを伝えられます。

### Q22. `input()`と`sys.stdin.readline()`はどう違いますか？【ex2】

**回答例：** `input()`はプロンプトを表示でき、末尾の改行を取り除いて返します。`readline()`は通常末尾の改行も含めて返すため、現在のコードでは`rstrip("\n")`で取り除きます。また、`readline()`は何も読めずEOFになった場合、例外ではなく空文字列を返します。

比較：Enterだけの場合、`input()`は`""`、`readline()`は`"\n"`です。現在のコードは改行除去後の空文字列を確認し、空入力とEOFのどちらでも保存を中止します。

### Q23. なぜ`strip()`ではなく`rstrip("\n")`なのですか？【ex2】

**回答例：** 入力の末尾の改行だけを除き、ファイル名の先頭や末尾にある空白を勝手に消さないためです。`strip()`は空白やタブなども除去するため、入力したファイル名が変わる可能性があります。

### Q24. stdin・stdout・stderrとは何ですか？【ex2】

**回答例：** stdinは標準入力、stdoutは通常の出力、stderrはエラー出力の経路です。通常は入力がキーボード、出力はどちらも画面につながっていますが、それぞれ別のファイルやパイプへ接続できます。Unix系では対応するファイル記述子は0・1・2です。

### Q25. `[STDERR]`と付ければstderrに出力されますか？【ex2】

**回答例：** いいえ、接頭辞はただの文字列です。出力先は`sys.stderr.write(...)`によって決まります。通常の`print("[STDERR] ...")`はstdoutに出ます。

### Q26. なぜ入力前に`sys.stdout.flush()`を呼びますか？【ex2】

**回答例：** `write()`したプロンプトには改行がなく、バッファに残ってすぐ表示されない可能性があります。入力待ちになる前にプロンプトを出力するために呼びます。ファイル保存先のディスクへの永続化を指示しているわけではありません。

### Q27. stderrに出したことをどう実演しますか？【ex2】

**回答例：** シェルで`1>通常出力.log 2>エラー.log`のように別々のファイルへリダイレクトします。存在しないファイルを指定して実行し、通常メッセージと`[STDERR]`付きのエラーが別々に保存されることを確認します。

### Q28. ex0〜ex2でも`with`を使った方が簡単では？【共通要件】

**回答例：** 簡単に書けますが、この課題ではex3より前の使用が禁止されています。そのためex0〜ex2では`try/finally`で手動で閉じ、ex3では必須の`with`を使っています。

### Q29. 型ヒント・mypy・flake8の役割を説明してください。【共通要件】

**回答例：** 型ヒントは引数や戻り値などの想定する型を示します。mypyはその型の整合性を静的に検査します。flake8は書式や未使用のimportなどを検査します。型ヒントを書くだけで、実行時に引数の型が強制されるわけではありません。

### Q30. なぜ`if __name__ == "__main__":`がありますか？【現在の実装】

**回答例：** ファイルを直接実行したときだけ`main()`を呼ぶためです。importしたときはデモが自動実行されず、関数を呼び出して検証できます。ex3をimportしただけで出力ファイルが作られることも防げます。

### Q31. `secure_archive()`の結果を保存するとき、なぜ`result[0]`を確認していますか？【ex3】

**回答例：** 読み込み失敗時の`result[1]`はファイル内容ではなくエラーメッセージだからです。成功フラグを確認せず保存すると、エラー文を新しいファイルに書いてしまいます。

### Q32. このコードで防げることと、防げないことは何ですか？【深掘り対策】

**回答例：** 指定したI/Oエラーや文字変換エラーを捕捉して通知し、開いたファイルを閉じる処理を行います。一方、書き込み途中の失敗で元の内容を復元することや、停電時の完全な保存は保証していません。例外処理があることと、すべてのデータ損失を防げることは別です。

## 実演の練習

課題の`04`ディレクトリで実行します。作成する入力・出力は一時ディレクトリに置きます。テスト用のコマンドなので、提出コードで使用できる関数の一覧とは分けて考えてください。

```sh
review_tmp=$(mktemp -d)
printf 'alpha\nbeta\n' > "$review_tmp/input.txt"
```

**1. ex0：正常な読み込みと、存在しないファイル**

```sh
python3 ex0/ft_ancient_text.py "$review_tmp/input.txt"
python3 ex0/ft_ancient_text.py "$review_tmp/missing.txt"
```

説明すること：成功時の内容表示、失敗時に捕捉する例外、失敗後に処理を続けない理由。

**2. ex1：変換・保存・上書き・保存中止・EOF**

```sh
printf '%s\n' "$review_tmp/output.txt" | python3 ex1/ft_archive_creation.py "$review_tmp/input.txt"
cat "$review_tmp/output.txt"
printf '%s\n' "$review_tmp/output.txt" | python3 ex1/ft_archive_creation.py "$review_tmp/input.txt"
printf '\n' | python3 ex1/ft_archive_creation.py "$review_tmp/input.txt"
python3 ex1/ft_archive_creation.py "$review_tmp/input.txt" < /dev/null
```

説明すること：行ごとの`#`追加、`"w"`の動作、空入力とEOFの違い。

**3. ex2：通常出力とエラー出力の分離**

```sh
python3 ex2/ft_stream_management.py "$review_tmp/missing.txt" 1>"$review_tmp/stdout.log" 2>"$review_tmp/stderr.log"
cat "$review_tmp/stdout.log"
cat "$review_tmp/stderr.log"
```

説明すること：接頭辞と出力先は別物であること、リダイレクトの1と2の意味。

**4. ex3：操作指定の省略、読み込み失敗、無効な操作指定**

```sh
python3 -c 'import sys; from ex3.ft_vault_security import secure_archive; print(secure_archive(sys.argv[1]))' "$review_tmp/input.txt"
python3 -c 'import sys; from ex3.ft_vault_security import secure_archive; print(secure_archive(sys.argv[1]))' "$review_tmp/missing.txt"
python3 -c 'import sys; from ex3.ft_vault_security import secure_archive; print(secure_archive(sys.argv[1], "invalid"))' "$review_tmp/input.txt"
```

説明すること：任意引数のデフォルト値、各タプルの意味、`with`を抜けるタイミング。

権限不足も練習する場合は、自分で用意した一時ファイルの読み取り権限を外して試します。`/etc/master.passwd`はOSによって存在や権限が異なるため、どの環境でも同じ結果になる例とは説明しないでください。
